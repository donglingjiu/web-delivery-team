# 后端最小实践

## 选型决策树

- 只要表单收集/展示 → 无后端，静态托管 + 第三方表单收集。
- 轻量 API（CRUD、少量用户）→ 轻框架 + SQLite/托管数据库。
- 完整应用（用户系统、权限、事务）→ 主流框架 + 关系库 + 迁移脚本。

## 数据建模

1. 列实体与关系（谁包含谁、一对多还是多对多）。
2. 每表列名、类型、约束（非空/唯一/默认值）。
3. 先写迁移脚本再写代码。

## API 设计

- REST 命名：名词复数资源、动作放 HTTP 方法里。
- 统一响应结构：成功/失败/分页格式先定下来。
- 每个端点写清：方法、路径、入参、出参示例、错误码。

## 安全红线

1. 所有入参校验，不信任客户端。
2. 密钥/连接串走环境变量，绝不进代码和提交。
3. 密码只存哈希；鉴权用成熟方案，不自造加密。
4. CORS 只放行需要的来源。

## 自检

接口全部可用 curl 走通？错误路径有处理？数据库连接失败应用不崩？
